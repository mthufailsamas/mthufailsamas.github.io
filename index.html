01

AI automation & document intelligence | n8n, Python, Gemini, PostgreSQL

End-to-End AI Invoice Approval Automation

Problem
Finance teams repeatedly read and re-key fields from visually different invoice files, then check totals, references, duplicates, and approval requirements before data can reach accounting.
My Contribution
Designed and built the complete workflow: multi-file intake, three n8n automations, Gemini document extraction, Python business controls, PostgreSQL state and audit history, human review and approval, and idempotent delivery to an ERP sandbox.
Approach
Users can upload up to 20 invoices in one batch. n8n creates one job per file, starts extraction and validation, and automatically routes approval-ready, review, and unreadable outcomes. A failed file remains isolated, while approved records continue through a retry-safe accounting handoff.
System Safeguards
Every invoice receives its own source hash, workflow state, and audit history. Fixed controls verify file integrity, required fields, totals, currencies, references, dates, duplicates, and approval routing before data can reach the accounting handoff.
20 filesMaximum Upload Batch
3Event-Driven n8n Workflows
Per-fileFailure Isolation

Operational ResultThe workflow moves finance work from re-keying every visible field to uploading a batch, reviewing extracted values, resolving exceptions, and authorizing the final handoff. Each invoice is processed independently, so one unreadable document does not stop the remaining batch.

System OutputThe workflow produces structured invoice records, exception queues, approval tasks, searchable history, audit events, and duplicate-safe ERP records. n8n coordinates the process, Gemini reads the documents, Python enforces fixed controls, and PostgreSQL preserves workflow state.

03

Time-series forecasting | Python, XGBoost

Rainfall Forecasting with XGBoost and Grid Search

Problem
Estimate next-day rainfall in Sumenep Regency from recent meteorological conditions while preserving temporal order during model evaluation.
My Contribution
Implemented the end-to-end forecasting workflow from data validation and lag construction through temporal model evaluation and experiment reporting, and served as first author on the resulting peer-reviewed publication.
Approach
Constructed one-day lagged predictors from BMKG meteorological observations and trained XGBoost regression models with fold-wise Min-Max scaling and Grid Search across 243 hyperparameter configurations.
Validation
Evaluated the models using 10-fold TimeSeriesSplit, fitting preprocessing only on each training fold to preserve temporal order and reduce data leakage.
0.9152MAAPE
11.9566RMSE (mm)
10Temporal Folds

Interpretation & LimitationsThe selected model captured recurring rainfall behavior within the evaluated observations, while larger rainfall peaks remained more difficult to predict. Performance therefore reflects this dataset and evaluation design rather than guaranteed forecasting accuracy for extreme rainfall or other regions.

EvidenceOriginal BMKG observations are restricted. The public repository provides a synthetic same-schema dataset for reviewing and reproducing the workflow.

Clinical classification | Python, XGBoost

Thyroid Cancer Recurrence Classification with XGBoost, Information Gain, and Grid Search

Problem
Classify differentiated thyroid cancer recurrence while examining whether feature selection could reduce the encoded feature set without sacrificing predictive performance.
My Contribution
Implemented the data audit, feature encoding, fold-local Information Gain selection, checkpointed model search, and multi-metric evaluation workflow for this collaborative academic project.
Approach
Prepared the 383-record UCI source dataset using explicit numeric, binary, ordinal, and nominal feature handling, then combined entropy-based Information Gain feature selection with XGBoost and Grid Search.
Validation
Performed Information Gain selection separately within each training fold and evaluated models using 10-fold cross-validation and pooled out-of-fold predictions to avoid global feature-selection leakage.

95.37%F1-score
98.05%Specificity
98.60%ROC-AUC

Interpretation & LimitationsThe model showed strong discrimination within the experimental dataset, but the dataset is relatively small and the results do not establish clinical readiness. External validation and clinical-domain review would be required before practical medical use.

05

Data engineering & monitoring analytics | Python, PostgreSQL

DWDM Optical Sensor Monitoring with Change-Point and Degradation Detection

Problem
Transform distributed DWDM optical telemetry into structured monitoring and investigation outputs for a project-stage operational workflow.
My Contribution
Implemented the Python/PostgreSQL data pipeline, data-quality and failure logic, statistical change-point and degradation detectors, paired-sensor analysis, API outputs, priority workflow, and monitoring interface as a Junior Programmer at PT Aplikanusa Lintasarta.
Data & System Context
Approximately 400 directional sensors combining native 5-minute PRTG optical-power telemetry with ENIMS sensor, link, direction, endpoint, and location metadata.
Approach
Built an incremental, checkpoint-based workflow from metadata synchronization and telemetry collection through processed observations, contiguous failure events, penalized PELT change-point detection with robust statistical regime checks, Theil-Sen slope and serial-correlation-corrected Mann-Kendall gradual-degradation analysis, paired and opposite-direction sensor evidence, priority ranking, and a local dashboard API.
Analytical Safeguards
Statistical detectors use only clean observed values. Missing, downtime, zero-coverage, and low-signal failure intervals remain operational evidence but are excluded from statistical change and trend analysis rather than analytically interpolated.
~400Directional Sensors
5 minTelemetry Cadence
3Operational Views

OutputOutputs include failure events, persistent downward change points, gradual degradation trends, paired-sensor evidence, sensor-priority rankings, Operations Board, Event Explorer, and Management Overview views.

Interpretation & LimitationsStatistical evidence supports operational investigation but does not confirm a physical root cause. The system does not claim quantified production impact and is a local/internal project-stage implementation rather than an internet-facing production service.

Statistical modeling | Forecasting

Rice Price Forecasting with ARIMA and Walk-Forward Validation

Problem
Forecast monthly medium and premium rice prices in East Java using an interpretable statistical time-series approach.
Approach
Modeled the two price series separately using ARIMA, with ADF-based differencing, ACF/PACF inspection, candidate-order evaluation, and residual diagnostics.
Validation
Used the first 80% of the 60 monthly observations as the initial history and evaluated one-step-ahead forecasts sequentially through expanding-window walk-forward validation.
2.08%
Medium MAPE
1.82%
Premium MAPE

Interpretation & EvidenceThe selected models tracked monthly price movements closely during the evaluated period, but structural market or policy changes may not be captured by historical ARIMA dynamics. The workflow and public East Java price data are available in the repository.
