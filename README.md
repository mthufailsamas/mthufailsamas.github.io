# M. Thufail Alwannabil Samas - Data and AI Portfolio

[View the live portfolio](https://mthufailsamas.github.io/)

This repository contains the professional Data and AI portfolio of M. Thufail
Alwannabil Samas. It connects selected
work across data analysis, statistical modeling, machine learning, practical
data engineering, and applied AI automation with professional experience,
publication, certification, and technical background.

## Portfolio Overview

The featured case studies cover:

- DWDM Optical Sensor Monitoring with Change-Point and Degradation Detection,
  developed as professional project-stage work at PT Aplikanusa Lintasarta;
- a Retail Sales Forecasting &amp; Planning System with chronological Ridge and
  XGBoost evaluation, a versioned model artifact, reusable batch inference,
  local FastAPI delivery, Docker packaging, and contract tests;
- AI Service Request Automation with FastAPI, n8n, PostgreSQL/pgvector, local
  Ollama models, human review, downstream delivery, and scheduled recovery;
- next-day Rainfall Forecasting with 2-stage and direct Tweedie XGBoost,
  Grid Search, and annual TimeSeriesSplit evaluation;
- Thyroid Cancer Recurrence Classification with Python, XGBoost,
  scikit-learn, Information Gain, and Grid Search;
- Rainfall Forecasting with TensorFlow/Keras BiLSTM and Grid Search; and
- Rice Price Forecasting with statsmodels ARIMA and Walk-Forward Validation.

Each case study focuses on the problem, contribution, system or analytical
workflow, validation evidence, practical output, and limitations. Public
project repositories are linked where available. Confidential work is
presented only through approved summaries and non-sensitive visual material.

## Technical Implementation

The website uses semantic HTML, responsive CSS, and vanilla JavaScript. It
includes:

- responsive desktop and mobile layouts;
- a permanent dark interface with a consistent color palette;
- brief one-shot heading entrances and native interaction feedback, honoring
  reduced motion and keeping all content visible without animation;
- project-context filters for Professional, Independent, and Academic work,
  with visible cards renumbered sequentially from `01`;
- an automatic release-freshness check that replaces a cached page with the
  current published revision;
- accessible navigation and structured page sections;
- mobile navigation that remains available when JavaScript is unavailable,
  with keyboard focus recovery and scrollable menus on short screens;
- optimized `1920x1080` WebP evidence visuals with a consistent Full HD
  workflow composition for the 2 independent projects, original result visuals
  for the academic projects, and responsive profile, hero, and
  social-preview images; and
- downloadable English resume.

The site has no frontend framework, build step, package manager, backend,
analytics, or tracking.

## Local Preview

The portfolio is a static website and requires no installation. Open
`index.html` directly in a browser or serve the folder locally:

```bash
python -m http.server 8000
```

Then open `http://localhost:8000`.

## Maintenance and Verification

Keep career copy and project evidence in `index.html`; content is never
generated by JavaScript. `styles.css` groups design tokens, base styles,
components, responsive rules, and reduced-motion-safe transitions. `script.js`
initializes navigation, project filters, and optional one-shot heading motion
independently inside a private scope. The inline release
guard stays in the HTML so a cached page can discover a newer deployment.

Run the development-only checks with Node.js 18.17 or newer:

```bash
node --test tests/site.test.cjs
```

The dependency-free suite checks release alignment, local references, image
attributes, asset budgets and orphans, menu state, filter numbering, and
fail-open release handling, one-shot motion cleanup, API fallbacks, and changes
to reduced-motion preferences. It does not replace browser testing: before
publishing, inspect desktop and narrow mobile layouts, keyboard navigation,
project details, full-size visuals, and the no-JavaScript fallback. Change
the `860px` navigation breakpoint in both CSS and JavaScript together.

For a visible revision, update the matching release markers and sitemap date,
version each changed public asset URL, and verify the GitHub Pages deployment.
Remove temporary QA artifacts; do not retain duplicate assets or backups.
